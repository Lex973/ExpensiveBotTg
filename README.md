# Expense Bot

Telegram-бот на русском для личного учёта финансов. Python 3.12+, локальная SQLite или удалённая Turso. Интерфейс — одна редактируемая карточка с inline-кнопками. Поддерживаются локальный long polling и serverless webhook на Vercel. Mini App относится к следующему этапу и здесь ещё не реализован.

## Запуск

1. Создайте бота через [BotFather](https://t.me/BotFather), получите токен.
2. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN` локально. Не публикуйте токен и не отправляйте его в чат.
3. В папке проекта выполните `python run.py`.
4. Откройте личный чат с ботом и отправьте `/start`.

Бот работает, пока запущен процесс и есть интернет. Для круглосуточного режима нужен постоянно работающий компьютер или сервер. Запускайте один экземпляр на одну базу и токен. Если на этом токене ранее использовался webhook, отключите его перед polling. Бот не отключает webhook автоматически.

Бесплатное serverless-развёртывание описано в [DEPLOY_VERCEL.md](DEPLOY_VERCEL.md). Оно использует webhook и внешнюю Turso вместо локального файла. Для этого режима установите зависимости из `requirements.txt`.

Настройки: `DATABASE_PATH` (по умолчанию `data/expense.db`) для локального SQLite; `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` для удалённой базы; `UTC_OFFSET_HOURS` (по умолчанию +5, Екатеринбург). Текущая версия использует один часовой пояс для всех пользователей, одну валюту RUB и не подключается к банкам.

## Возможности

- Расходы, доходы и переводы: создание, полное изменение, удаление с подтверждением. Дата и заметка, защита от повторного сохранения операции.
- Категории доходов и расходов: создание, переименование, удаление из выбора с сохранением истории.
- Бюджет каждой расходной категории на конкретный календарный месяц: потрачено, не потрачено или перерасход. Бюджеты не переносятся автоматически на следующий месяц.
- Обычные, накопительные и инвестиционные счета; начальный остаток, изменение реквизитов, текущий баланс. Удаление возможно, если нет связанных операций и целей.
- Цели: сумма, срок, отдельный счёт, прогресс и необходимый ежедневный темп. Одна цель на счёт, чтобы одни накопления не учитывались дважды. Пополнение — перевод между счетами.
- Аналитика: текущая неделя, месяц, последние 30 дней, произвольный период до 10 лет; сравнение с предшествующим отрезком той же длины, категории, доли, количество операций, средние расходы, доля сохранённого дохода.
- Для отдельного счёта: баланс в начале и конце периода, изменение в рублях и процентах, последние 7 дат изменения. Суммы переводов не считаются заработком или тратами.
- CSV всех операций выбранного периода, включая переводы и операции удалённых категорий. Для счёта включены входящие и исходящие переводы. UTF-8 BOM, разделитель `;`, защита текстовых полей от формул таблиц.
- Локальный расчёт по расходам и целям, опциональное подключение внешнего ИИ-сервиса.

Начальные остатки считаются средствами, существовавшими до всей истории операций. Изменение начального остатка меняет исторические балансы. Рыночной переоценки инвестиций и котировок нет: проценты и комиссии вносятся вручную. Отрицательный баланс допустим. Доходы минус расходы — остаток доходов, а не гарантированный баланс или прибыль инвестиций. При нулевой базе процентное изменение не вычисляется.

## Интерфейс

Обзор → добавить расход / доход → сумма → счёт → категория → дата и заметка → проверка → сохранение.

Обзор → счета / история / категории / цели / аналитика / персональный разбор.

`/cancel` и переход в раздел отменяют незавершённый ввод. Состояние и ID карточки сохраняются в SQLite. Кнопки старых карточек игнорируются. Бот сначала подтверждает callback, затем обновляет карточку через `editMessageText`; если редактирование невозможно, пытается удалить старую и присылает новую. Введённые пользователем сообщения удаляются по возможности. Telegram может запретить удаление старых сообщений. Выгрузки CSV остаются отдельными сообщениями.

Обычный бот использует оформление Telegram: HTML, типографику, emoji, текстовые индикаторы прогресса и кнопки. Собственные цвета, шрифты, интерактивные графики и полноценные вкладки требуют Mini App.

## Подключение ИИ

Реализован адаптер **пользовательского HTTPS-сервиса**, а не прямая интеграция конкретного поставщика. Для подключения нужен сервер-адаптер с контрактом ниже. Без него кнопка показывает локальный расчёт и явно сообщает, что это не ИИ.

В `.env` задайте `AI_ENDPOINT=https://your-service.example/analyze` и `AI_API_KEY=...`. Бот делает POST с JSON и заголовком `Authorization: Bearer ...`. Сервис должен вернуть `{"analysis": "Текст анализа на русском"}`. Таймаут 35 секунд, перенаправления запрещены. Ключ общий для развёртывания; пользователи не вводят ключи в Telegram.

Поля запроса: `currency`, `amount_unit` (kopecks), `start`, `end`, `summary` (доходы, расходы, сравнение, категории и дневные итоги), `accounts` (тип и баланс), `goals` (название, целевая сумма, накоплено, срок), `instruction`.

Каждый запуск требует нажатия «Разрешить и проанализировать» после пояснения, какие данные уходят провайдеру. Telegram ID, токен бота, имена счетов и заметки операций не отправляются. Названия категорий и целей отправляются. Стоимость и хранение данных зависят от выбранного сервиса. Секреты не записываются в журналы. Вызов API поставщика нужно реализовать на стороне сервиса-адаптера.

## Проверка

```powershell
python -m unittest discover -s tests -v
python -m compileall -q expense api scripts run.py
```

Тесты проверяют точность денег, изоляцию пользователей, переводы, перерасчёт после изменения и удаления, архив категорий, сравнение периодов, бюджеты, цели, дубли и навигацию через подставной Telegram API. Для проверки настоящей доставки нужен токен и живой чат.

## Структура и следующий этап

`expense/core.py` — данные и расчёты для SQLite/libSQL. `expense/ui.py` — русские экраны и формы. `expense/bot.py` — Telegram polling, CSV, адаптер ИИ. `expense/webhook.py` и `api/webhook.py` — защищённый Vercel webhook. `scripts/` — перенос базы и регистрация webhook. `tests/` — проверки.

Для Mini App можно повторно использовать Ledger; потребуется HTTP API, проверка Telegram initData на сервере, полноценная авторизация, адаптивный интерфейс и графики. Сейчас HTTP API не публикуется. Для большого числа пользователей понадобится ограничение нагрузки, миграции схемы и переход на серверную БД. Первый запуск создаёт схему автоматически.

Данные лежат локально в SQLite без шифрования. Ограничьте доступ к каталогу. Для резервной копии остановите бота и скопируйте целиком `data/`; при работающей базе используйте SQLite backup API, а не копирование только файла `.db`.

API Telegram: [официальная документация](https://core.telegram.org/bots/api).
